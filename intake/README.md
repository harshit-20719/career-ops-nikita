# Intake

`QUESTIONNAIRE.md` is the one-time setup interview. Its answers are the input to
everything else in the workspace — the master resume, the target list, comp strategy,
and every drafted message.

## How to use it

1. Copy it to where the filled version will live:
   - repo is private → `intake/answers.md`
   - repo is public → `private/intake.md` (gitignored, so it stays local)
2. Fill in what you can. Skip what you can't — `?` is a legitimate answer.
3. Hand it back to me. I'll build the master resume, seed `targets/companies.csv` and
   `contacts/contacts.csv`, set the comp strategy, and draft the story bank from it.

Tier 1 is enough to start. Tiers 2–4 make the output substantially better, but they
don't have to happen in one sitting.

## Why it's a file rather than a conversation

Sessions end and containers get reclaimed. A committed answers file means the next
session — days or months from now — starts with full context instead of re-asking.
When something changes (a new floor, a new target title, a role that ends), edit the
file; it's meant to be living, not a one-time form.

## The rule that matters

Nothing in here gets embellished on the way into a resume. If a number isn't in the
answers, it doesn't appear in a bullet. Invented accomplishments survive exactly until
an interviewer asks a second question about them, and the cost of that is the offer.
